# Оновлення форуму 0.8 → 0.9

Це тестовий кандидат 0.9 на основі оригінального архіву 0.8. Візуальне приймання за вимогою 100% ще не завершено.

## Встановлення
1. Зробіть резервну копію всього чинного форуму та узгоджену SQLite-копію `storage/forum.sqlite` (SQLite backup API / `.backup`; не копіюйте лише основний файл під час активного WAL).
2. Увімкніть закритий режим. Розпакуйте файли архіву в корінь форуму поверх коду 0.8. НЕ видаляйте storage та assets/avatars.
3. Архів не містить forum.sqlite і не замінює дані. Перший запит застосує транзакційну додаткову міграцію; ID, тексти, паролі та старі parent_post_id збережуться.
4. PHP 8.1+ з PDO_SQLite, mbstring, GD (WebP), fileinfo. Перевірено на PHP 8.5.10. Apache має дозволяти .htaccess / mod_rewrite. Для nginx окремо забороніть /storage/, /app/, виконання скриптів у /assets/avatars/ і направте /robots.txt на /robots.php.
5. Для НОВОЇ інсталяції: /install.php. Режим за замовчуванням закритий. Для наявної БД інсталятор нічого не перезаписує. Після першого встановлення приберіть install.php.
6. Перевірте /admin/, пошук, тему, реєстрацію, аватар, robots.txt. Не відкривайте публічно до візуального приймання. Відкриття потребує окремої позначки підтвердження в налаштуваннях.

## Відкат
Поверніть код із оригінального архіву 0.8 або 0.7; додані поля не видаляйте. За необхідності повного відкату використайте узгоджену резервну копію БД. Нові відповіді дублюють зв’язок у parent_post_id для сумісності з 0.8.

## Обмеження кандидата
- Google/Telegram вмикаються лише реальними параметрами середовища. Повторна авторизація з профілю оновлює зовнішнє фото; доступний також вибір збереженого аватара identity. Google authorization code + PKCE і Telegram Widget з перевіркою підпису реалізовані, але ще не перевірені з реальними credentials на домені. Див. SOCIAL-SETUP.md.
- Підписка зберігає вибір у БД; доставки email-сповіщень немає.
- Піксельна відповідність усім трьом референсам не підтверджена. Див. VISUAL-STATUS.md у checkpoint.
