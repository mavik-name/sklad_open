# MAVIK.NAME — ALL PAGES LOCALE PARITY OVERRIDE

Дата: 2026-08-19
Статус: **HIGHEST PRIORITY OVERRIDE**

Цей документ уточнює і перевизначає будь-які попередні двозначні трактування локалізації.

## Головне правило

**УСІ сторінки сайту мають одну й ту саму структуру, дизайн, набір блоків, функціональність і змістову модель у всіх локалях. Відрізняється тільки мова.**

Це стосується без винятків:
- головної / титульної сторінки;
- каталогу книг;
- сторінок книг;
- читанок;
- музики;
- блогу;
- сторінки автора;
- контактів;
- безпеки/захисту;
- `/mavik/`;
- анонсів;
- усіх інших public routes.

## Титульна / головна сторінка

`/` і `/en/` — це **та сама сторінка**, той самий template/component tree, ті самі блоки в тому самому порядку, той самий дизайн і той самий зміст за змістом.

Різниця лише в тому, що:
- `/` підставляє українські значення з `lang`/locale layer;
- `/en/` підставляє англійські значення з `lang`/locale layer;
- майбутні локалі підставляють свої переклади з власних lang files.

Не допускається окремий EN-home layout, окремий EN HTML, спрощена англійська головна або інший набір блоків.

## Усі інші сторінки

Той самий принцип діє для кожної пари локалей:

`same route type → same template → same components → same design → same semantic content → different language values`.

Для статичних сторінок зміст має бути семантично 1:1 у перекладі.

Для редагованого контенту існує один logical object з локалізованими payload; visibility може окремо вмикатися/вимикатися для кожної локалі.

Якщо перекладеного payload для конкретної локалі немає або він неповний — representation цієї локалі має стан `hidden`, а не окрему заглушку/спрощену сторінку.

## Локалізація

Уся оболонка, canonical static content та системні тексти локалізуються **через lang files**. Не створювати окремі locale-specific templates/CSS/layout copies.

## Управління

Адмінка одна. Будь-яка контентна операція має explicit locale scope: одна локаль, кілька або всі активні локалі. CORE/design зміни автоматично діють на всі локалі.

## Release gate

Будь-який реліз, у якому хоча б одна локаль має інший shell, layout, component tree, design або інший зміст статичної canonical page, — **FAIL**.

Обов'язкова visual parity перевірка desktop + mobile для головної і всіх основних route types.

Правильна модель:

**ONE SITE → ONE CORE → ONE DESIGN → ONE PAGE MODEL → ONE LANG LAYER → ONE ADMIN → MANY LOCALES.**
