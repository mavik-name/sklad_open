# MAVIK.NAME — SEO IDENTITY CANON

Дата: 2026-08-19
Статус: **HARD SEO CANON / ОБОВ'ЯЗКОВО ДЛЯ R216**

## Ідентичність

Пошукова та структурована ідентичність сайту має однозначно зв'язувати:
- `MaVik`;
- `Мавік`;
- `Віктор Макарчук`.

Це одна авторська/брендова сутність, а не три незалежні назви.

## Обов'язково в R216

1. **Головна сторінка**: природний видимий текст має зв'язувати `MaVik`, `Мавік` і `Віктор Макарчук` без keyword stuffing.
2. **Сторінка автора**: те саме семантичне зв'язування має бути присутнє у видимому тексті сторінки автора.
3. **`<title>`** головної та сторінки автора має містити достатню ідентифікацію автора/бренду та бути locale-aware; не створювати штучного переліку ключових слів.
4. **Schema.org `WebSite`**: canonical name + `alternateName` мають включати доречні варіанти `MaVik` / `Мавік` і зв'язок із автором там, де це семантично коректно.
5. **Schema.org `Person`** для Віктора Макарчука: `name` = `Віктор Макарчук` у UA-контексті, `alternateName` має містити `MaVik` і `Мавік`; EN-локаль використовує locale-appropriate presentation, але сутність лишається тією самою.
6. `WebSite`/`Person` structured data повинні мати стабільні `@id`, щоб пошуковик міг зв'язати бренд і автора між сторінками та локалями.
7. Canonical/hreflang не змінювати заради цього пакета; застосувати пакет без створення дубльованих URL.
8. OpenGraph/Twitter та JSON-LD не повинні суперечити видимому title/name/author identity.
9. Boss/SEO self-test R216 має перевіряти на головній і сторінці автора: title, `WebSite`, `Person`, `alternateName`, валідний JSON-LD та відсутність конфліктних canonical/hreflang.
10. SEO-пакет має працювати для UA та EN через спільний CORE + locale/lang/content layer, без дублювання окремої SEO-логіки в content patches.

## Після live-публікації R216

Після фактичної установки R216 на mavik.name:
1. перевірити live HTML/JSON-LD головної та сторінки автора;
2. перевірити sitemap/canonical/hreflang;
3. повторно подати потрібні ключові URL на індексацію через Google Search Console (головна, сторінка автора та інші сторінки, де SEO identity materially changed);
4. виконати штатний IndexNow/Bing submission;
5. зафіксувати результат у SITE-WORK-JOURNAL.

Google Search Console reindex є **post-deploy дією**, бо він має посилатися на вже опублікований live R216, а не на локальну збірку.

## Заборона

- не додавати meta keywords як заміну нормальній семантиці;
- не повторювати `MaVik / Мавік / Віктор Макарчук` неприродно по всіх блоках;
- не створювати окремих дубльованих сторінок лише під різні написання бренду;
- не робити різні Person-сутності для `MaVik`, `Мавік` і `Віктор Макарчук`.

Правильна модель: **одна сутність автора/бренду, кілька альтернативних імен, узгоджені visible text + title + structured data**.
