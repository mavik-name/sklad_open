## ЖОРСТКИЙ КАНОН ПІСЛЯ R198 — CORE FREEZE

Після канонізації R198 подальше звичайне наповнення сайту робити **лише контентними PATCH/OVERLAY-пакетами без втручання в CORE**.

CORE R198 не змінювати під час:
- додавання/редагування книг і перекладів;
- додавання EPUB, обкладинок, ілюстрацій, музики та інших медіафайлів;
- додавання/редагування блогів і статичних контентних матеріалів;
- оновлення описів, метаданих і контентних даних;
- звичайної SEO-синхронізації, яку вже вміє чинний CORE/Boss.

Контентний patch може містити лише потрібні контентні файли, медіа, контентні дані та згенеровані публічні індекси/SEO-артефакти, якщо це необхідно для синхронності. **Не переписувати CORE-код, шаблони, PHP/JS/CSS-логіку, service worker, PWA-механіку, Boss-функціонал або архітектуру.**

Якщо колись реально потрібна зміна CORE — це окрема структурно-функціональна задача, окремий повний кандидатний реліз від R198 і окреме пряме затвердження користувача. Контентний patch не має права непомітно змінювати CORE.

## Головний архітектурний канон

Будь-яка зміна контенту через Boss або patch має бути доведена до повної узгодженості публічного сайту та пошукових роботів.

Створення / редагування / приховування / показ / переміщення / видалення повинні синхронно враховувати, де релевантно:
- публічну навігацію;
- внутрішні посилання;
- sitemap.xml;
- robots/noindex;
- canonical;
- hreflang/локалізацію;
- structured data;
- IndexNow;
- внутрішній SEO-аудитор.

Активні архітектурні правила R198:
- один багатомовний core;
- одна Boss-адмінка;
- одна модель даних;
- українська версія без мовного префікса;
- інші мови через префікси на кшталт `/en/`;
- ручний вибір мови та explicit URL мають пріоритет;
- browser autodetect — fallback;
- `/_site-state/` не перезаписується штатним deploy;
- PWA встановлюється із сайту;
- у мобільному меню немає нумерації;
- у читалці один центральний control `▶ Читати ↔ ⏸ Пауза`;
- натискання на потрібне місце тексту запускає озвучення звідти;
- у режимі слухання використовується Screen Wake Lock, включно з паузою, з повторним захопленням після повернення сторінки у visible state.
